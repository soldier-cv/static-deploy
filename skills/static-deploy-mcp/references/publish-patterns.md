# 发布套路与链接改写（踩过的坑）

## 单文件 HTML 原型
- 用一个自包含 HTML（无构建依赖、可离线打开）发布，服务端会自己打包成站点目录并回一个 URL。
- **入口解析**：zip 里带单一顶层目录（`demo/index.html`）时，服务端只在根找 `index.html` 会回落到不存在的链接 → 发布后**必须自己 curl 一次那个返回链接断言 200**，不要只看接口返回成功。

## 图片
- 图片走上传接口拿直链；不要把图片塞进 HTML 里再整包发（体积大、手机加载慢）。
- 上传体积上限是两层的（nginx 层 + 服务端解析层），超限会给明确错误而不是 500。

## 两个入口吃的东西不同
- 服务端有 REST 上传口与 MCP 工具两条路：**REST 口一般只收 zip**（直接丢单 HTML 会报 `File is not a zip file`），单文件请走 MCP 工具的 html 参数。具体参数名以 `/setup` 为准。

## 链接改写（最容易出错）
- 服务端回显的 URL 是按**请求 Host** 推导的：从 `127.0.0.1` 调用会得到 `http://127.0.0.1:8088/sites/<id>/...`。
- 发给用户前把它换成 `http://100.64.0.88:8088/sites/<id>/...`，并**自己先 curl 一次断言 200**，再发链接。
